Advanced discovery limits

These per-module limits are separate from the ZAP total request budget. Passive scanning can keep processing a large response after requests finish. ZAP waits up to this budget, retains partial alerts on expiry and logs queue progress.

GAU archive providers

GAU · Archive discovery

Balanced avoids repeated slow archive lookups for hosts with no historical results. Expanded includes Common Crawl, with independent timeouts and cooldowns. A zero-result archive query does not prove that the host has no endpoints.

Protocol endpoints

GraphQL and raw WebSocket checks use matching same-origin URLs already found by discovery, or the paths below. Blank inputs skip tools with no applicable endpoint. Paths apply to the selected asset and are not saved in cookies.

GraphQL checks metadata and query-only native signatures; no application mutations, subscriptions, cyclic fragments or schema reconstruction. WebSocket checks validate opening handshakes without sending frames; Socket.IO negotiation and authenticated hijack testing are outside this profile. Native Corsy checks HTTP CORS; wildcard access or anonymous acceptance is not itself a credential leak.

VCS metadata review needs a directory URL ending in / and never fetches repository objects or history. S3 review applies only to bucket-root URLs such as https://bucket.s3.amazonaws.com/ or https://s3.amazonaws.com/bucket/. It requests no object contents or writes. Takeover review needs provider/DNS corroboration and never registers or claims services. Unresolved hostnames can run DNS review when Takeover is enabled; HTTP tools skip until public DNS resolves.

Query reference comparisons

IDOR-Forge · limited GET profile

Use explicit reference IDs you are authorized to test. This keyless, anonymous profile sends at most four GET requests to one path and never follows redirects. Shared inputs apply to each selected target; use per-target overrides when IDs differ. Without these inputs the module skips.

Similarity is a review signal. This profile cannot prove object ownership or missing authorization; verify candidates using two authorized test accounts. Credentials, mutations, broad payload fuzzing and the upstream GUI are outside this profile. Reference values and response bodies are omitted from results and logs.

Per-target module overrides

Optional JSON object keyed by an exact selected URL or asset ID. Each value overrides shared module inputs for matching targets, including race, nosql, IDOR fields, source_text and sbom_text. Unspecified fields keep shared values; use null for a replay profile or an empty string to clear an input. Shared replay profiles run on each selected target unless target_origin binds them to one origin. Give race tests separate fresh fixtures where endpoints share state.

Optional module inputs

Optional inputs stay in this job's memory. Source/SBOM content is not included in saved results. Shared artifacts can be inspected for each selected target. Use per-target overrides for different artifacts. Full pipeline skips tools whose inputs are absent.

Semgrep reviews one supplied source file using ten bundled rules. Source is never executed or uploaded to a rule service. This profile does not infer source code from a website URL. Language preference is saved; pasted source stays unsaved. WAFW00F runs before payload scanners in Guided mode and records vendor context; a WAF fingerprint is not a vulnerability.

Race-condition replay

Enable Race replay in the module library. Shared profiles apply to selected targets; per-target overrides support different fresh fixtures. The profile can repeat POST operations: use disposable test fixtures and identities. It sends two sequential requests to a control fixture, then two overlapping requests to a distinct fresh fixture. Only one two-request burst is allowed; HF timing is best effort.

Use a JSON success predicate. An optional GET verifier must report a non-negative integer counter starting at zero for each fixture. Exactly one sequential effect must be established before the parallel test. Without state verification, duplicate success responses are informational, since idempotent acknowledgements can look like a race.

Request format and limits

Optional target_origin binds this profile to one scheme/host/port; mismatches skip. Without it, the shared profile applies to each selected target. request.path is a same-origin path without a query string. GET uses query; POST uses json_body. field names a top-level string field. control_value and parallel_value identify separate fresh fixtures. success uses an RFC 6901 JSON pointer and equals value. verification.request is GET-only; its field selects the fixture, and pointer reads its counter. At most four replay requests plus four optional state reads. Redirects, 429, 5xx and oversized responses stop the profile without retries.

NoSQL HTTP operator review

Enable NoSQL HTTP review and configure a known-working baseline request and success predicate. Six paced requests compare the baseline, a negative scalar, an inert object, equality controls and a not-equal operator. This checks Mongo-style HTTP parsing, not direct MongoDB/CouchDB/Redis ports. Operator support may be intentional; findings require review of the API contract.

For GET, the selected query field is replaced with bracket-form operator parameters; for POST, the selected top-level JSON string field is replaced with typed objects. Only equality/not-equal operators are generated. No scripts, sleeps, data enumeration or credential extraction.

Private batch inputs

Request paths, headers, bodies, fixture values and predicates stay unsaved and clear after queuing. Shared request headers apply to every target where that shared profile runs. Set target_origin to bind a profile to one HTTP(S) origin, or use per-target overrides for separate credentials and fixtures. Optional test-account Cookie/Authorization headers stay on each applicable origin; environment credentials and account profiles are not imported. These fields are never saved in cookies or job options. Other settings and module choices keep their saved preferences.

Batch scans create one job per selected target, with one shared replay slot on HF, verified TLS, no redirects, no retries, 64 KiB response cap. Normal pacing applies between requests/phases; only the explicit two-request race burst overlaps. Profiles skip when absent, even in Full pipeline.
